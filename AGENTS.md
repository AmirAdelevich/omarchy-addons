# Правила для агентов

Репозиторий — набор аддонов для Omarchy: виджет бара `BarWidget.qml`, меню
`addons-menu.sh` и установщики, которые меню вызывает. Эти правила
обязательны при любой правке.

## Язык

- Текст для пользователя — меню, сообщения скриптов, README, комментарии —
  на русском.
- Коммиты — на английском, в повелительном наклонении, тело коммита
  объясняет «почему», а не пересказывает дифф.
- Новые файлы документации и подсказки `--help` тоже на русском.

## Нумерация меню

`addons-menu.sh` — единственный источник номеров. Меню состоит из блоков,
у каждого блока свой номер, внутри блока нумерация начинается с 1. Номер
пункта пишется подряд: первая цифра — блок, остальные — пункт.

```
1. ПРОГРАММЫ      11, 12, … 111
2. ПЛАГИНЫ        21, 22
3. НАСТРОЙКИ      31, 32, 33
4. ОБОРУДОВАНИЕ   41
5. РАБОЧИЙ СТОЛ   51
```

Требования:

- У каждой программы, плагина, настройки и т.д. **свой номер** вида
  `блок` + `пункт` без разделителя: `13` — блок 1 пункт 3, `111` — блок 1
  пункт 11. Настройки не смешивать с плагинами и программами.
- Номер блока — одна цифра, поэтому блоков не может быть больше девяти.
  Число пунктов в блоке не ограничено: `110`, `115` и т.д.
- Разбор ввода обязан понимать и форму с точкой (`1.11`) для
  совместимости, но подсказки и README показывают короткую форму.
- Ввод принимает несколько номеров через пробел или запятую:
  `13 21 33`. Дубликаты игнорируются.
- Новый пункт добавляется в конец своего блока через `item`. Порядок и
  номера существующих пунктов не меняются: на них ссылаются README и
  привычки пользователей.
- Новый блок добавляется через `section` только если в нём несколько
  пунктов и он не подходит ни к одному существующему.
- Действие в меню — одна строка вида `program:chrome`, `plugin:fans`,
  `setting:nogaps`; обработка — в функции `run`. Никакой логики установки
  прямо в меню.
- `--list` и `--run` обязаны работать с теми же номерами, что и
  интерактивный режим. Ошибки нумерации объясняются по-русски: «нет блока
  N», «в блоке N нет пункта M», «формат: блок.пункт».
- Голый номер блока (`2`) — ошибка с подсказкой `2.1`, а не установка
  всего блока.

## Установщики

- Скрипты запускаются от обычного пользователя; `sudo` — только внутри и
  только для системных пакетов и файлов.
- Все установщики идемпотентны: повторный запуск ничего не ломает и
  сообщает «уже установлено / уже включено».
- `install-all.sh` ставит компоненты по именам (`chrome`, `code`,
  `tailscale`, …). Новый компонент — функция `install_<имя>` плюс запись в
  массив `components`; без аргументов скрипт по-прежнему ставит всё.
- Плагины ставятся только через `install-plugin.sh <имя>`; сторонний код
  берётся на закреплённом коммите из `desktop/sources.tsv`, не с ветки.
- Всё, что меняет конфиги, делает резервную копию и печатает её путь.
- У действий, которые можно отменить, есть обратный режим
  (`--remove`, `--gain`, отдельный пункт меню) и он описан в README.

## Bash

- `set -euo pipefail` в установщиках, `set -uo pipefail` в меню (ошибки
  пунктов обрабатываются вручную).
- В `trap ... EXIT` не использовать `[[ … ]] && …` как последнюю команду:
  под `set -e` это ломает код возврата. Писать `if [[ … ]]; then … fi`.
- Временные каталоги — через `mktemp -d` и очистку в трапе.
- Не печатать пароли и токены; не сохранять их в репозитории.

## Проверка перед коммитом

```bash
bash -n addons-menu.sh install-all.sh install-plugin.sh \
        install-mouse.sh install-no-gaps.sh install-sound-boost.sh \
        restore-desktop.sh
bash addons-menu.sh --list
bash addons-menu.sh --run 99     # должен вернуть код 2 и объяснить ошибку
bash addons-menu.sh --run 17 33  # короткая форма: блок 1 пункт 7, блок 3 пункт 3
```

- Не запускать в проверке пункты, которые ставят пакеты или меняют
  систему. Для проверки нумерации достаточно неверных номеров и `--list`.
- После правки меню обновить README: номера, примеры ввода, состав блоков.

## Версии и релиз

- `manifest.json` — версия аддона. Меняется при любом видимом для
  пользователя изменении: новые пункты, новые установщики, новое
  поведение. Формат — `MAJOR.MINOR.PATCH`.
- Правки только документации версию не меняют.
- Изменения уходят в `main` репозитория
  `AmirAdelevich/omarchy-addons`; рабочая копия — `~/omarchy-addons`.
- Git-идентичность задаётся локально:
  `AmirAdelevich <196453627+AmirAdelevich@users.noreply.github.com>`.

## Структура

| Файл | Назначение |
|------|------------|
| `addons-menu.sh` | Меню: блоки, номера, разбор ввода, `--list`/`--run` |
| `install-all.sh` | Программы по компонентам |
| `install-plugin.sh` | Плагины `fans` и `pulse` |
| `install-sound-boost.sh` | Усиление звука с лимитером, `--gain`, `--remove` |
| `install-mouse.sh` | Чувствительность мыши |
| `install-no-gaps.sh` | NoGaps |
| `microscope/install.sh` | Микроскоп H1600: просмотр, запись, фото, настройки |
| `restore-desktop.sh` | Снимок рабочего стола, профиль вентиляторов |
| `desktop/` | Снимок конфигов, плагинов и закреплённые ревизии |
| `manifest.json` | Манифест плагина и версия |
| `README.md` | Пользовательская документация |

Если правила меняются, обнови этот файл в том же коммите.
